# Repository security audit — 2026-09-20

## Findings and scope

**Confirmed malicious loader code existed in former remote branch tips and
earlier force-pushed revisions.** The initial local main at `818cab0` did not contain the
identified loaders. This audit uses static inspection; it does not establish
that a payload executed, that data was stolen, or who introduced it.

Inspected all 179 initially tracked files, local untracked source/configuration,
both remote branch tips, reflogs, unreachable objects, and older commits fetched
from the 11 push events returned by GitHub. The expanded object inventory covered
650 Git objects: 385 blobs and 63 commit objects (including the local clean
reconciliation commit). Examined executable configuration, package scripts,
lockfile origins/integrity, source networking/dynamic execution, SQL policies,
asset signatures, and credential indicators. Only inactive sample Git hooks were
present; no configured hooks path was found.

The source audit found no additional loader indicators outside the two paths
below. This is not a guarantee that every form of malware is absent. Third-party
package contents were not exhaustively reverse-engineered. No production
database, endpoint, deployment account, browser session, developer machine, or
cloud audit log was available for a runtime/forensic assessment.

| `public/fonts/fa-solid-400.woff2` | former `Sajawal_Pro_plan` tip `035b62e` | 30,037 bytes of JavaScript rather than a WOFF2 font; second loader copy |

Eight unique suspicious loader blobs were found across the expanded history:
six PostCSS variants and two fake-font variants. Their full SHA-256 hashes, Git
blob IDs, byte sizes, paths, and containing commits are recorded in
[incident-objects.json](incident-objects.json). No executable payload is copied
into this report or the CI fixtures.

The formerly affected PostCSS file at `7657dd9` fails a syntax-only check with
`Identifier 'createRequire' has already been declared`. Thus the current file
as-is would fail parsing before its loader runs. This does not make the payload
safe or establish whether earlier variants or the fake font were executed.
The fake-font path was not referenced elsewhere in the inspected branch tree.

The cleanup branches reconcile the rewritten histories while retaining the known
local PostCSS configuration and original ignore entries. They introduce no force
push or history deletion. Both cleanups are now merged: `main` at `4f4b117` and
`Sajawal_Pro_plan` at `64927c5`. Static scans of both merged tips pass.

## Other application security findings requiring database review

These are independent source-level authorization findings, not malware.
Production impact depends on deployed migrations, grants, and other controls.

| Severity | Location | Finding / required follow-up |
| --- | --- | --- |
| High | `src/lib/schema.sql:171-173` | Public profile SELECT includes email/date of birth; self UPDATE covers rows containing `is_premium`, `premium_plan`, `is_verified`, and ban fields. Verify column grants, private views, and server-controlled field protections. |
| High | `src/lib/fix-group-rls.sql:109` | Self-insertion policy allows a caller to join a known group ID and does not constrain the supplied membership role. Require an authorized invitation/admin action and constrain roles. |
| High | `src/lib/migration-v2-features.sql:119-149` | SECURITY DEFINER follow accept/reject helpers trust `p_user_id` without checking `auth.uid()`. Bind mutations to the authenticated recipient and restrict function grants. |
| High | `src/lib/migration-active-group-calls.sql:28` | Any authenticated user can delete active group-call records; insertion checks host identity but not group membership. Scope both operations to authorized group participants/hosts. |
| Medium | `src/lib/schema.sql:185` | Notification INSERT uses `WITH CHECK (true)`; verify callers cannot forge system messages or other users' notification metadata. |
| Medium | `src/lib/schema.sql:222-225` | Public storage SELECT and upload policy do not enforce the same per-user folder boundary used for updates/deletes. Review bucket privacy and private-gallery access against deployed storage policies. |

No SQL migrations were applied or authorization behavior silently changed as part
of the CI work. These findings need dedicated database verification and fixes.

The tracked `.env` contains frontend configuration and an `anon`-role Supabase
JWT, not a discovered service-role credential. Frontend anon keys are public by
design and rely on effective RLS. TURN credential fields and other frontend
configuration must never be treated as private server credentials. The new
ignore rules prevent adding new local env variants; existing tracked `.env`
history remains. No private-key/GitHub-token/AWS-key indicators were found in the
initial object scan. This is not a comprehensive secret-scanning attestation.

## Dependency and CI remediation

Initial npm lockfile audit: **27 vulnerable package entries** (1 critical, 18 high, 6 moderate,
2 low). Compatible lockfile updates plus Vite **6.4.3** reduce this to **4 moderate,
0 high, 0 critical** at audit time. Remaining advisory-bearing packages are
`react-router`, `react-router-dom`, `vitest`, and `@vitest/mocker`; npm proposes
major-version migrations for their complete remediation. No force-upgrade was
applied. The high/critical CI gate passes while continuing to report these.

The Vite upgrade addresses the Windows dev-server file-deny bypass documented in
[GHSA-fx2h-pf6j-xcff](https://github.com/advisories/GHSA-fx2h-pf6j-xcff).

CI adds static source/asset/credential tripwires before installing packages,
scanner regression tests, TypeScript checks, ESLint, the existing application
test, production build, a high/critical dependency gate, CodeQL security-extended
analysis, and Dependabot updates. Fourteen existing lint errors were corrected
with type annotations, type aliases, const declarations, and an ESM plugin import;
no lint rule was disabled. Application test coverage is currently only one
placeholder test and must not be represented as functional application coverage.

Validation uses a fresh temporary checkout, registry dependencies installed with
`--ignore-scripts`, and dummy build environment values. No compromised revision,
original node_modules directory, or loader was run. Build warnings about CSS
import ordering and bundle size are existing issues.
